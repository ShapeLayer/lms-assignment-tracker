# LMS 어댑터 작성 가이드

어댑터는 LMS의 강의·과제 페이지를 읽고 공통 `Assignment` 형식으로 변환합니다. 현재 구현된 어댑터는 전남대학교 LMS용이며, 새 파일을 추가하기만 하면 자동으로 등록되는 플러그인 구조는 아닙니다. 다른 LMS를 추가하려면 아래의 수집 코드와 서비스 워커, 대시보드의 URL 검증과 빌드 설정도 함께 연결해야 합니다.  

## 현재 동작 흐름

1. `core/background.ts`가 설치, Chrome 시작, 주기적 알람, LMS 탭 로드 또는 수동 요청에 따라 동기화를 시작합니다. 같은 시점의 동기화 요청은 하나의 작업을 공유합니다.
2. 서비스 워커는 `adaptor/offscreen.html`을 열고 `{ target: "jnu-adapter", type: "JNU_SYNC" }` 메시지를 보냅니다. 이 문서가 로드하는 `adaptor/jnu.ts`가 요청을 수신합니다.
3. 어댑터는 로그인된 LMS 세션을 이용해 과제 정보를 수집한 뒤 `{ assignments, warning }` 또는 `{ error }`를 반환합니다. `warning`은 일부 수집에 실패했지만 결과를 저장할 수 있을 때, `error`는 전체 동기화를 진행할 수 없을 때 사용합니다.
4. 서비스 워커는 반환된 과제의 URL과 ID를 검증해 기존 캐시와 병합하고, 동기화 시각과 경고를 저장합니다. 대시보드도 저장된 URL을 다시 검증합니다.

## 과제 데이터 형식

최종 정의는 `core/model.ts`의 `Assignment`와 `Attachment`를 따릅니다.

| 필드 | 설명 |
| ------------------------- | --- |
| `id`                      | LMS별 접두사와 해당 LMS에서 안정적인 과제 식별자. 예: `jnu:1483382`. 제목이나 표시 언어가 바뀌어도 동일해야 합니다. |
| `url`                     | 검증된 과제 상세 페이지 URL. 알림 클릭과 대시보드 링크에 사용됩니다. |
| `title`, `course`, `body` | 과제 제목, 강의 이름, 비 HTML 본문 텍스트. |
| `dueAt`                   | 마감 시각의 ISO 8601 문자열 또는 `null`. 마감일이 없거나 판별할 수 없을 때는 `null`입니다. |
| `startAt`                 | 선택 사항. 과제 시작 시각의 ISO 8601 문자열 또는 `null`. 없으면 캘린더는 최초 수집 시각을 사용합니다. |
| `firstSeenAt`             | 선택 사항. 최초 수집 시각의 Unix 밀리초. 기존 병합 로직이 최초 수집 시 `updatedAt`으로 채우고 다음 동기화에서도 유지합니다. |
| `status`                  | `pending`, `completed`, `unknown` 중 하나. 제출 여부를 확신할 수 없으면 `unknown`으로 둡니다. |
| `statusText`              | LMS가 표시한 원본 제출 상태 텍스트. |
| `updatedAt`               | 이번 수집 시각의 Unix 밀리초. |
| `attachments`             | 선택 사항. `{ name, url }` 배열. `url`은 검증된 첨부파일 주소여야 합니다. |

서비스 워커는 `pending` 과제에 대해 마감 알림을 발송하며, `unknown`은 캘린더의 미완료 수에는 포함되지만 알림 대상으로 간주되지는 않습니다.(\*캐싱된 과제의 새 상태가 `unknown`이면 병합 시 이전 상태를 유지함.)

## 새 어댑터 추가

### 1. LMS 화면과 인증 방식 확인

사용자가 접근을 허용한 계정에서 강의 목록, 과제 목록, 과제 상세, 마감일, 제출 완료·미제출 상태, 첨부파일을 확인합니다. 언어 설정, 로그인 만료, 권한 부족, 마감일 없음 등의 화면도 확인하세요. 비밀번호나 쿠키를 별도로 저장하지 않습니다.

`adaptor/jnu.ts`는 `credentials: "include"`로 기존 브라우저 세션을 사용합니다. 세션이 없거나 만료되면 수집을 실패로 보고 캐시는 유지합니다. LMS 탭이 열려 있다고 가정하지 마세요. 다만 쿠키의 `SameSite` 정책과 LMS 인증 방식에 따라 확장 프로그램의 요청에서 세션이 전달되지 않을 수 있으므로 실제 Chrome에서 확인해야 합니다.

### 2. URL 정책과 수집 코드 작성

`adaptor/`에 LMS 전용 TypeScript 파일과 URL 검증 함수를 만듭니다. `adaptor/jnu-urls.ts`, `adaptor/attachments.ts`, `adaptor/jnu.ts`가 예시입니다.

### 3. 메시지, 권한, 빌드 연결

- `manifest.json`의 `host_permissions`에 해당 LMS의 필요한 HTTPS 오리진을 추가합니다. 새 권한은 사용자에게 해당 사이트 접근 권한을 요청합니다.
- 현재 `adaptor/offscreen.html`은 `jnu.js` 한 개를 로드합니다. 새 어댑터를 같은 offscreen 문서에 함께 로드하거나 하나의 진입점에서 라우팅하도록 변경하세요.
- 어댑터의 메시지 리스너는 `sender.id === chrome.runtime.id`를 확인하고, 고유한 `target`과 메시지 타입을 사용합니다. 비동기 `sendResponse`를 사용하면 리스너에서 `true`를 반환합니다.
- `core/background.ts`의 동기화 호출, 수집 결과·저장된 데이터의 검증, LMS 탭 감지 조건, 알림 클릭 URL 검증을 새 어댑터에 맞게 추가 연결합니다.
- `dashboard/app.ts`의 저장 데이터 및 첨부파일 검증을 LMS별 정책으로 확장합니다. (\*새 LMS를 허용하는 과정에서 기존 오리진 제한을 제거하지 마세요.)
- `package.json`의 `build`는 현재 `adaptor/jnu.ts`만 esbuild로 번들합니다. 새 진입점을 번들하거나 공통 진입점에 포함하고, 필요한 정적 파일은 `scripts/copy-assets.mjs`에서 `dist/`에 복사합니다.

## 검증

`npm test`는 빌드 후 Node 테스트를 실행합니다. 새 어댑터에는 최소한 다음 사례를 추가하세요.

- 정상 강의·과제·첨부파일 추출, 중복 링크 제거, 언어별 제목과 상태, 마감일 없음.
- 제출 완료·미제출·알 수 없는 상태의 변환과 기존 캐시 병합.
- 외부 오리진, `data:`·`http:`, 유사 도메인, 잘못된 경로, 누락·중복 ID, 허용되지 않은 첨부파일 및 리디렉션 거부.
- 로그인 만료, 부분 실패, 요청 상한, 타임아웃, 동시 동기화 요청.
- 저장소에 남은 유효하지 않은 URL이 표시·알림·열기 경로를 통과하지 않는지 확인.

`tests/security.test.js`, `tests/attachments.test.js`, `tests/model.test.js`를 참고하세요. 테스트는 실제 로그인 세션을 대신하지 않습니다. `npm run build` 후 `dist/`를 Chrome에 로드하고 해당 LMS에서 로그인된 상태와 세션 만료 상태를 각각 확인하세요. 과제 목록, 상세 페이지, 첨부파일 링크, 완료 상태 갱신, 알림과 오류 표시가 실제 서비스에서 작동하는지도 점검합니다.
